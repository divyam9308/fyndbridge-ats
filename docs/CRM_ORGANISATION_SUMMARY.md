# CRM organisation summaries

The Add/Edit Client form places an optional About Organisation panel below the organisation/date row and above Contact 1. It has a 136px scroll area, bullet points, bold headings, manual editing and a Generate AI Summary action. The table previews five words in the column immediately after Organisation Name; View more opens the complete summary in a dialog.

## Rollout

Apply `supabase/migrations/20261021090008_crm_organisation_summary.sql` before deploying the application changes. It adds nullable `crm_clients.organisation_summary` and updates the existing service-only, security-invoker `crm_save` RPC atomically with its existing version checks and activity tracking. Existing records have no summary. The existing list RPC includes the field through its row JSON conversion. Applied to ATS FYNDBRIDGE (`owheruvatjcfqwsejnmo`) on 21 October 2026 as migration `20261021090008`. Read-only schema inspection confirmed the nullable JSONB field, summary-aware save function, SECURITY INVOKER, service-only execution grants and existing row-level security.

Company research uses `GEMINI_CRM_SUMMARY_MODEL` (default `gemini-2.5-flash-lite`) and the existing primary/secondary Gemini credentials. It does not inherit the email setting `GEMINI_CRM_MODEL`, which remains `gemini-3.5-flash-lite` by default. No new environment variable is required to select 2.5 for summaries; the optional summary setting overrides only research. It sends only the organisation name and optional sector hint to Google, with the Google Search tool enabled. Contact information and Gmail content are not sent. Source URLs and Google's Search suggestions accompany the summary. Source links use HTTPS; suggestions render in a sandboxed iframe without scripts or same-origin privileges. Summary text is rendered through React with a limited bold/link formatter, never raw HTML.

Google's pricing page lists free-tier Google Search grounding for Gemini 2.5 Flash-Lite up to 500 requests/day, shared with 2.5 Flash and subject to project quotas. Google currently limits 2.5 model access to users who previously used those models. Access has not been tested with the project's keys. The feature reports access/model errors if 2.5 is unavailable, without silently switching to a model that requires paid search. Email and CV parsing keep their existing model selection. See https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash-lite and https://ai.google.dev/gemini-api/docs/deprecations#gemini-2.5-flash-models . The screenshot's original generic error discarded the provider status/body and produced no runtime diagnostic, so that individual failure's exact Google error cannot be recovered from existing logs.

Provider errors now distinguish billing/tier, missing model, key/access, quota, request rejection and Google overload, with structured `crm_organisation_summary_failed` logs containing the authenticated user ID and safe provider status/reason/model metadata. Raw Google messages, response bodies, organisation names, contact details, URLs and API keys are excluded. This diagnostic correction is local until deployed; it does not itself grant Google Search access.

Generation is explicit, with a 25-second timeout per provider, a secondary-key attempt only on quota errors, and per-process caching/coalescing to reduce duplicate calls. A best-effort 30-second per-user cooldown applies to uncached requests; it is not a distributed rate limit. Cached summaries expire after 15 minutes. Neither generation nor opening the popup saves a record: Save persists the optional summary with the rest of the form. Changing the organisation name clears the draft overview to avoid saving another company's information. Changing name/sector or closing the form aborts the browser request and prevents stale results being applied; an already-running provider call may still finish on the server.

Research without web grounding, ambiguous companies and truncated answers produce an inline error rather than an invented or partial overview. Regeneration failures retain the previous draft. The prompt targets 200–250 words but permits shorter results when reliable information is sparse. Google Search grounding has its own quotas/pricing: https://ai.google.dev/gemini-api/docs/generate-content/google-search

Newly generated summaries request seven bullets: Business, Products & markets, Headquarters, Employees worldwide, Employees in India, Annual revenue and Growth. Headcount must include its reporting date/year; India figures must be distinct from worldwide totals. Annual revenue includes currency, reporting year and entity/consolidation scope. Growth prioritises reported revenue growth with comparison periods, or clearly labelled, dated qualitative expansion if no verified percentage is available. Primary annual reports and official disclosures take precedence. Key figures and headings are bold, with source citations. Required metrics omitted from the response receive an explicit "Not verified in available public sources" bullet. Estimates/ranges must be attributed and dated; missing values are never zero or invented. Existing saved summaries change only when the user regenerates/edits and saves them. No additional AI call or automatic retry is introduced for filling these points.
